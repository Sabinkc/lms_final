## 2. Typography

- **Font — `CONFIRMED`, revises v0.2.** No `@font-face`, no Google Fonts `<link>`, no custom font import anywhere in `src/` (checked `App.css`, `index.css`, and all Landing/auth components). The app uses Tailwind v4's **default `font-sans` utility class** explicitly in places (e.g. `Plansubscriptionpage.tsx`), which resolves to Tailwind's built-in stack: `ui-sans-serif, system-ui, sans-serif, "Apple Color Emoji", "Segoe UI Emoji", "Segoe UI Symbol", "Noto Color Emoji"` — a similar *idea* to v0.2's guessed stack but not textually identical (v0.2 guessed the older Bootstrap-style `-apple-system, "Segoe UI", Roboto...` stack, which doesn't appear in source). v0.2's Flutter recommendation (pick **Inter** or **Roboto** via `google_fonts` rather than chasing an OS-default stack) still stands — a system-font stack isn't portably meaningful for Flutter either way.
- **Type scale — `CONFIRMED`, real distribution.** Grep-counted `text-*` utility usage across all `.tsx`: `text-xs` (1113 uses), `text-sm` (847), `text-base` (115), `text-lg` (101), `text-xl` (113), `text-2xl` (87), `text-3xl` (49), `text-4xl` (20), `text-5xl` (9). This is a **dense, data-table-heavy admin UI** — the overwhelming majority of text is `xs`/`sm` (labels, table cells, badges), with `2xl`+ reserved for landing-page hero copy and dashboard KPI numbers. This directly contradicts v0.2's `ASSUMPTION` of adopting Material 3's Display/Headline/Title/Body/Label scale as a starting point — Material 3's scale skews much larger/looser than what this product actually uses. **Recommendation revised**: bias the Flutter type scale down — body/label text should be small and dense (12–14px) to match the product's real information density, with only dashboard KPIs and section headers going larger (20–30px, matching `text-xl`–`text-3xl`'s real usage weight).
- **Font weight — `CONFIRMED`.** Real usage, heaviest end skewed: `font-bold` (1126), `font-semibold` (700), `font-medium` (612), `font-extrabold` (38), `font-black` (32), `font-normal` (9, almost never used explicitly). The UI leans bold/semibold by default rather than regular weight for most text — worth carrying into Flutter's `TextTheme` (bump default body weight up from `w400`).

> **`RESOLVED` for the Flutter app (2026-09-01):** implemented in `AppTypography` (`lib/core/theme/app_typography.dart`) — Inter, default body weight bumped to `w500`/titles to `w600`–`w700` per the weight finding above. One deviation from the letter of this section's `google_fonts` suggestion: Inter is **vendored as a local variable-font asset** (`assets/fonts/Inter-Variable.ttf`, registered in `pubspec.yaml`) rather than fetched at runtime via the `google_fonts` package's CDN — `google_fonts` was tried first, but its runtime HTTP fetch failed outright in the test environment (`flutter test` threw `Failed to load font... fonts.gstatic.com`) and would carry the same offline risk for real users on unreliable school wifi. A local asset is deterministic in both cases with no functional difference to the recommendation itself (still Inter, still `google_fonts`' *intent*, just not its runtime-fetch *mechanism*).

## 3. Spacing

**`CONFIRMED`, revises v0.2's `ASSUMPTION`.** Grep-counted Tailwind spacing-scale utility usage (`p-*`, `px-*`, `py-*`, `gap-*`, etc.) across all `.tsx` confirms Tailwind's default 4px-based scale is used directly and heavily, with a clear concentration around the small-to-medium end: `gap-2`/`py-2` (~575–584 uses each), `gap-3` (456), `gap-1` (443), `px-4` (441), `py-3` (399), `px-3` (391), `p-4` (243), `py-1` (242), `px-2` (219), `gap-4` (214), `p-3` (207), `px-6` (182), `p-5` (168), `py-4`/`px-5` (165 each), `p-6` (159). This **confirms v0.2's guessed 4px-base/8pt-grid recommendation was directionally correct** — the real scale in play is effectively Tailwind's own (`1`=4px, `2`=8px, `3`=12px, `4`=16px, `5`=20px, `6`=24px), with `2`/`3`/`4` (8/12/16px) as the dominant working set for gaps and padding, and `4`–`6` (16–24px) for card/section padding. Recommend mapping Flutter spacing constants directly onto this: `4, 8, 12, 16, 20, 24` as the primary scale, matching real usage weight (not the coarser `4, 8, 12, 16, 24, 32, 48` v0.2 guessed, which skipped 20 and jumped straight to 32/48 that aren't heavily used here).

> **`RESOLVED` for the Flutter app (2026-09-01):** `AppSpacing` (`lib/core/theme/app_spacing.dart`) had silently stayed on the old `ASSUMPTION`-flagged `4, 8, 12, 16, 24, 32, 48` guess even after this section was written — corrected to the confirmed `4, 8, 12, 16, 20, 24` scale above and put into actual use for the first time (previously defined but 0 call sites anywhere in the app) in the new dashboard/shell widgets.

## 4. Border radius (kept from v0.2 — independently consistent with this pass)

v0.2 extracted this from the live site's compiled CSS as directly-observed real values, and this pass's grep of the repo source's `rounded-*` utility usage confirms the same shape is genuinely in heavy use (not just theoretically available): `rounded-xl` (817 uses), `rounded-full` (459 — avatars/pills/icon buttons), `rounded-2xl` (430 — cards/modals), `rounded-lg` (256 — buttons/inputs), `rounded-md` (39), `rounded-3xl` (37 — large modal sheets, e.g. the login modal's `sm:rounded-2xl`/`rounded-t-2xl`), `rounded-sm` (4), `rounded-xs` (1).

| Token | Value |
|---|---|
| `radius-xs` | 2px (.125rem) |
| `radius-sm` | 4px (.25rem) |
| `radius-md` | 6px (.375rem) |
| `radius-lg` | 8px (.5rem) |

- **Navigation IA — `CONFLICT` with v0.2.** v0.2 assumed a **bottom navigation bar** with ~4–5 items (Dashboard, core module, Notices/Schedule, Chat, Profile), reflecting a mobile-first guess.   > **`RESOLVED` for the Flutter app (2026-09-01):** the open "how many bottom-nav items" decision is now made — each role's shell (`lib/core/router/role_shell.dart`, `lib/core/dashboard/role_dashboard_config.dart`) uses **Home + 2 promoted tabs + More** (4 items), landing close to v0.2's original 4–5 guess despite that guess having no real evidence behind it at the time.
